## 1. サービス概要

**TCG Advance** — 日本のトレーディングカードゲーム（TCG）プレイヤー・ショップ・大会主催者を
1つのプラットフォームでつなぐコミュニティアプリ。

| 項目 | 内容 |
| --- | --- |
| 形態 | モバイルウェブアプリ（PWA、モバイルファースト 430px） |
| URL | https://tcg-advance.vercel.app |
| ステータス | 開発中（MVP稼働中、順次機能追加） |
| ログイン | Google / X / LINE / Facebook（Supabase Auth、LINEは自前Edge Function） |
| 対応タイトル | ポケカ / MTG / ワンピース / デュエマ / 遊戯王 / ヴァイス（横断型） |

## 2. 解決する課題（事業概要書より）

1. **イベント情報の分散** — ショップのSNS・サイト・Googleマップに散在、1か所で見られない
2. **プレイヤー同士のつながりが薄い** — 大会で会っても交流が一時的で終わる
3. **マナー・競技品質の担保** — 対戦相手の評価・報告の仕組みがない
4. **戦績管理の手間** — スプレッドシートや手書きで管理、振り返りができない
5. **ショップ・主催者の集客課題** — SNS発信力がないと参加者が固定化する

## 3. プロダクト構成（コードの実態）

- **本体アプリ**（リポルート）: React 18 + TypeScript + Vite。Supabase（PostgreSQL + RLS + Edge Functions）接続。Vercel自動デプロイ
- **Tournament Organizer**（`tournament-organizer/`）: シングルエリミ大会の情報を本部→フロア/配信/ステージ/クライアントへ共有するツールの独立モック。localStorageのみ、バックエンドなし。事業概要書には未登場＝**位置づけ未定**
- **UIプロトタイプ資産**: 本体の `src/pages/` に検索・大会進行・デッキ管理などのモック画面一式と `src/data/mockData.ts` が残っており、Phase 2以降の実装土台になる

## 5. ターゲット・市場（事業概要書より）

- 🎮 **プレイヤー**: 大会参加層（全レベル）。仲間づくり・戦績管理・ショップへの動線
- 🏪 **カードショップ**: 大会を定期開催する専門店。集客・口コミ・常連化が課題
- 🏆 **大会主催者**: 自主大会オーガナイザー。参加者管理・評判向上の仕組みが必要

市場規模の想定: 国内TCG市場は推計1,000億円超（カード販売額ベース）、競技人口は主要タイトルで数百万人規模、カード専門店は全国3,000〜5,000店以上。
（※出典未記載の推計値。事業計画では要裏取り）

## 6. ビジネスモデル（想定・未実装）

現フェーズは無料でユーザー獲得優先。収益化ルートは4案:

| 収益源 | タイミング | 内容 |
| --- | --- | --- |
| ショップ向けSaaS | Phase 2〜3 | イベント管理高度化・CSV・QR受付、月額サブスク |
| プレミアムプレイヤー | Phase 2〜3 | 戦績詳細分析・デッキ統計・カスタムプロフィール、月額課金 |
| 大会スポンサー枠 | Phase 3〜 | メーカー・ショップのスポンサー表示、通知枠販売 |
| データ分析提供（BtoB） | Phase 3〜 | 匿名化した参加動向・デッキメタデータをメーカー・小売へ |

## 7. 差別化（事業概要書より）

最大の差別化点は **「GPS位置証明つきチェックイン」×「TCG文化に根ざした相互評価（GG/マナー）」** の組み合わせ。
「参加を証明した上で評価し合う」仕組みは X や既存スコアアプリにない。全タイトル横断・ショップ側ツール統合も差別化要素。

## 9. 開発体制・技術

個人開発（オーナー兼PM）+ AI開発支援（Claude）。フロント React/TS/Vite、バックエンド Supabase、
ホスティング Vercel（GitHub連携自動デプロイ）、GPSは Web Geolocation API + Haversine。
開発の回し方は `design/links.md` / `design/styleguide.md` を参照（モックモード・スクショ自動化あり）。
