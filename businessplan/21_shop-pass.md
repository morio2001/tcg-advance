# NESTパス（TCGショップ月額パス）— 事業設計 v0.1

> `10_business-plan.md` §6.2 の本命ユーザー課金「TCGショップ月額パス」のブレイクダウン。
> オーナー仮説: 「アド取るの大好き」なTCGプレイヤーと月額優待パスは相性が最良。
> 価格・優待メニュー・景表法観点はオーナー最終判断（🔶マーク）。
> 最終更新: 2026-08-06（事業計画セッション）

## 1. コンセプト

**「持ってるだけで、TCGライフ全部がちょっとお得になる」月額パス。**

- ユーザー: 加盟ショップでの優待＋NEST内の特典。月に2〜3回店に行く人なら確実に元が取れる=「アド」が明確
- ショップ: **加盟無料**。対価はパス会員の送客と来店データ。claim済み店舗の次のステップとして自然に接続
- NEST: 初のアプリネイティブな継続収益（MRR）。非対戦日にも「パスを持ってる」という存在理由が生まれる

## 2. 三者の損得設計（この事業の核）

| 立場 | 出すもの | 得るもの |
| --- | --- | --- |
| ユーザー | 月額料金 | 加盟店優待（すぐ元が取れる）＋アプリ内特典 |
| ショップ | 優待の原資（**限界費用が低いものから選ぶ**） | パス会員の来店増・新規客・来店データ（将来のCRM）。金銭負担ゼロ |
| NEST | パス運営・送客・アプリ | サブスク収益100%（当面ショップと金銭のやり取りをしない） |

原則: **お金の流れを「ユーザー→NEST」の一本にする**。ショップとの精算を作らないことで、
加盟のハードルが「書類1枚」になり、景表法・契約・経理の複雑さも最小化される。

## 3. 優待メニュー（🔶 たたき台）

加盟店は下のメニューから**1つ以上**を選んで提供する（JAF優待方式。店ごとに内容が違ってよい）:

| メニュー | ユーザーの体感価値 | 店の実コスト |
| --- | --- | --- |
| 店舗大会のエントリー割引 or **優先受付** | 高（枠争いのある人気大会では優先権が最も刺さる） | 低 |
| パス会員限定イベント（月1のパス会員会など） | 中〜高 | 中（運営の手間） |
| 購入時サプライ品プレゼント/割引 | 中 | 低〜中 |
| プレイスペース優待（**有料スペースの店のみ**: 無料/割引。相場は有料店で数百円/日〜、専用スペース業態で350〜500円/h） | 店による | 低（空席の限界費用ほぼゼロ） |
| 買取・購入の優待（%上限つき） | 高 | 中〜高（🔶 希望する店だけ。強制しない） |

- ⚠️ **前提の裏取り結果（2026-08調査）**: デュエルスペースは「無料開放」の店がかなり多く、有料化は一部のトレンド（マナー・回転率対応）に留まる。**プレイスペース優待はパスの価値の主軸に置けない**。主軸は上表の順の通り「大会優先枠・限定イベント」＝希少性のある優待に置く
- 設計原則: **「店が痛まない優待」を標準にする**。痛む優待（値引き系）は店の任意オプション
- アプリ内特典も併設: パス限定バッジ/称号、シーズン振り返りの詳細版、（将来）チアード自主大会の優先エントリー
- ⚠️ 景表法上の整理（優待が「景品類」に当たらない設計等）はオーナー管掌

### 3.5 プライズ循環 — 自主大会×加盟店の協賛関係（オーナー決定 ✅）

パスの優待（店→ユーザー）と逆向きの、**NESTから店へ価値が流れる仕組み**を対にする:

- **チアードの自主大会（スタジオ開催）のプライズを「近隣加盟店の利用券」にする**（例: 優勝2万円分）。法的整理もしやすい形（オーナー判断）
- 原資は年3,000万のアクティベーション予算（`10_` §6.4）。媒体に払うはずだった広告費が、そのまま加盟店の売上・来店に変わる
- 効果の連鎖:
  1. 店: プライズ原資が現金相当で入り、優勝者+観戦者が来店する → **「NESTは客と金を連れてくる」**という加盟動機。優待メニュー（§3）を出す心理的負担が消える
  2. ユーザー: 賞品が「近所の店で使える」ことで大会→店舗の回遊が生まれ、利用時のログ・チェックインがまた資産になる
  3. NEST: 大会（C層）・パス加盟網・アクティベーション予算が1本の循環でつながる
- パス会員特典との束ね: パス会員は自主大会の**優先/割引エントリー**（§3の「大会優先枠」の最上位版。自社大会なら原資も自分でコントロールできる、他社に真似できない優待）

## 4. 価格（🔶 たたき台）

- 基準案は **月額480〜980円のレンジで、プリセールスの反応を見て決める** 🔶（プレイスペース有料が相場と言えないことが判明したため、v0.1の「980円・来店2〜3回で回収」という単純な回収ロジックは取り下げ）
  - 「元が取れる」の再設計: 大会エントリー割引100〜200円×月2〜3大会 ＋ サプライ特典 ＋ 限定イベント/優先枠という**積み上げ型**の価値提示になる。単価の柱が細い分、**980円を張るなら優先枠・限定イベントの魅力が必須**。それが弱いエリアでは480〜600円が現実的
  - 創業期プラン（先行1,000人限定 月480円・永年）で初速をつける案は維持 🔶
- 年額プラン（2ヶ月分お得）は Phase 2 で追加
- 無料トライアル: 初月無料より「協賛大会の参加者に1ヶ月無料コード配布」の形が良い（`10_` §6.4 のアクティベーションと連動、配布数を制御できる）

## 5. 密度条件 — 「売っていいエリア」の定義

パスの価値はエリア内の加盟店密度そのもの。薄いエリアで売ると「使える店がない」→解約→悪評になる。

- **開始条件: 同一エリア内に加盟店10店以上**（うち週次大会開催店5店以上）が揃うまで、そのエリアではパスを販売しない
- 展開順序: GTMエリアで加盟店を先に集める（claim済み店舗への案内が営業リスト）→ 条件達成 → パス販売開始 → 隣接エリアへ横展開
- アプリ上は「あなたのエリアの加盟店マップ」が購入判断の材料になる（買う前に元が取れるか自分で確認できる）

## 6. 収支の目安（作業仮説・🔶 係数はStage 1の実測で更新）

| 前提 | 値 |
| --- | --- |
| GTMエリアのアクティブユーザー | 3,000人（Stage 2想定） |
| パス転換率 | 5〜10%（YAMAP有料率20%の半分以下で保守的に） |
| 月額 | 980円 |
| **MRR** | **15〜30万円/月** |

- 1エリアで月15〜30万円=固定費(`10_` §8)の5〜10倍。エリアを増やすほど線形に積み上がる
- 変動コストは決済手数料(3.6%前後)とサポートのみ。粗利率9割超
- 解約率の目標: 月5%以下（優待を1回でも使った会員の解約率は大きく下がる想定 → 「初回優待利用」をオンボーディングKPIにする）

## 7. アプリ実装への要求（Phase B〜C。`20_`の後続）

1. パス会員証画面（店頭提示用。会員状態・有効期限・エリア）— 最小はこれだけでよい
2. 加盟店マーク＋優待内容の表示（店舗ページ・マップ）
3. 優待利用の記録（店頭で店員がタップ or 会員がセルフ記録）→ 送客実績としてショップに見せるデータになり、CRM SaaS（Stage 3）の種になる
4. サブスク決済（Stripe想定。ネイティブ移行時のストア手数料問題は開発セッションで検討）
5. パス限定バッジ・称号（既存バッジ基盤に載せる）

## 8. 加盟店オペレーション

- 営業順序: 連携済みの仲のいいショップ → claim済み店舗 → GTMエリアの未claim店（パスを餌にclaimも進む）
- 加盟条件: 優待メニュー1つ以上の提供、店頭ステッカー掲示。契約は簡易な規約同意のみ
- 店側への約束: 加盟無料・いつでも退会可・送客実績データの月次共有（→ この共有レポートがCRM SaaSの営業材料に育つ）

## 9. リスクと対策

| リスク | 対策 |
| --- | --- |
| 優待の不正利用（会員証の使い回し） | 会員証画面に本人認証済みプロフィール・当日ワンタイム表示。高額優待の店にはセルフ記録でなく店員タップを推奨 |
| 加盟店の離脱（送客を実感できない） | 月次の送客実績レポートを自動化。優待は「痛まないメニュー」を標準にして負担感を残さない |
| 密度不足での見切り発車 | §5の開始条件を守る（10店未満のエリアでは売らない） |
| 「使わない月」の解約 | パス限定バッジ・シーズン特典などアプリ内価値で非来店月を埋める。年額プランで平準化 |

## 10. 検証プラン（作る前に売る）

1. **Stage 1中にプリセールス**: 連携ショップ5店に優待メニュー表を見せ、「加盟するか」「どのメニューなら出せるか」を確認（店側の検証）
2. 協賛大会で「こういうパスが出たら月980円で入る?」をアンケート＋事前登録リスト化（ユーザー側の検証。事前登録率10%超なら青信号 🔶 閾値はオーナー判断）
3. 両方通ったら Phase B〜C で実装、GTMエリア限定でローンチ
